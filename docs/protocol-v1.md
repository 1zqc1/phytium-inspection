# 飞腾智检通信协议 V1

## 适用范围

本协议用于飞腾 Linux、飞腾 FreeRTOS 独立核和 STM32 之间的业务消息。Linux 与 FreeRTOS 间可由 RPMsg 承载同一业务字段；飞腾与 STM32 间从 115200 bps、8N1 UART 起步。协议代码不访问串口或操作系统，由平台适配层负责收发字节。

## 帧格式

所有多字节整数使用小端序。帧最大 128 字节，CRC 覆盖从 `version` 到 `payload` 的全部字节，不覆盖两字节帧头和 CRC 本身。

| 偏移 | 长度 | 字段 | V1 规则 |
|---:|---:|---|---|
| 0 | 2 | magic | 固定 `A5 5A` |
| 2 | 1 | version | 固定 `01` |
| 3 | 1 | type | 消息类型 |
| 4 | 2 | payload_length | 0 至 108 |
| 6 | 4 | session_id | 每次 MCU 或控制器启动后建立的新会话号 |
| 10 | 4 | job_id | 工件事件号，同一件物品全链路保持一致 |
| 14 | 4 | seq | 单会话严格递增的命令序号，0 无效 |
| 18 | 0 至 108 | payload | 按消息类型解释 |
| 18+N | 2 | crc16 | CRC-16/CCITT-FALSE，小端序 |

CRC 参数为多项式 `0x1021`、初值 `0xFFFF`、输入输出均不反射、结果不异或。字符串 `123456789` 的校验值应为 `0x29B1`。

## 消息类型

| 值 | 名称 | 作用 |
|---:|---|---|
| 0x01 | HELLO | 建立会话并交换能力 |
| 0x02 | HEARTBEAT | 连接存活和状态摘要 |
| 0x10 | ARRIVED | STM32 报告新工件到位 |
| 0x11 | CAPTURE_REQUEST | 调度端要求 Linux 获取当前工件新帧 |
| 0x12 | RESULT | Linux 返回类别、置信度和模型版本 |
| 0x20 | SET_ROUTE | 授权设置合格或复检通道 |
| 0x21 | RELEASE | 授权放行当前工件 |
| 0x22 | COMPLETE | STM32 报告出口确认和动作完成 |
| 0x30 | ACK | 已接收并通过协议检查，不代表机械动作完成 |
| 0x31 | FAULT | 报告故障状态和原因 |

## 安全和时序规则

- 帧头、版本、类型、长度或 CRC 错误时丢弃整帧，不触发动作。
- `session_id` 不匹配表示旧会话消息，必须拒绝。
- `job_id` 不等于当前工件时必须拒绝。
- 命令序号必须在当前会话中严格递增；重发同一序号只能得到拒绝或幂等应答，不能再次执行动作。
- 识别和授权期限从 STM32 本地检测到物件到位时开始，收到重发或迟到消息不会重置期限。
- V1 初始识别授权预算为 1000 ms；机械动作超时由实物测量后配置。
- 心跳初值为 100 ms；300 ms 未收到有效心跳时禁止接纳新动作。该数值在实板测试后允许调整并记录版本。
- 公共控制器当前按 300 ms 固定门控：在忙碌状态发生心跳超时后锁存故障，迟到心跳不解除故障；须人工清障并建立新会话。业务层只能将完成帧校验、会话检查和消息类型校验的心跳交给控制器。
- 低置信度、图像质量不合格或模型无法判断的工件进入复检通道。

## 固定测试帧

以下 23 字节帧用于不同平台核对字节序和 CRC：

```text
A5 5A 01 12 03 00 44 33 22 11 88 77 66 55 DD CC BB AA 02 34 12 8E A8
```

其字段为 `RESULT`、会话 `0x11223344`、工件 `0x55667788`、序号 `0xAABBCCDD`、负载 `02 34 12`，CRC 为 `0xA88E`。
